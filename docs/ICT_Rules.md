# ICT Rules

This document defines the initial ICT concepts Project Sentinel will support. These rules are starting guidelines and should be refined through testing, chart review, and trader feedback.

## Market Structure

- Identify bullish, bearish, or ranging conditions.
- Track breaks of structure and shifts in market structure.
- Prefer setups aligned with higher-timeframe context.
- Treat unclear structure as a reason to wait.

## Liquidity

- Mark obvious buy-side liquidity above recent highs.
- Mark obvious sell-side liquidity below recent lows.
- Watch for liquidity sweeps before continuation or reversal ideas.
- Avoid entries directly into nearby opposing liquidity without justification.

## Fair Value Gaps

- Detect potential fair value gaps after displacement.
- Prefer gaps created by strong directional movement.
- Require context before treating a gap as actionable.
- Do not use a fair value gap alone as a trade signal.

## Order Blocks

- Identify candidate order blocks near displacement moves.
- Prefer order blocks that align with structure, liquidity, and session context.
- Reject weak or isolated order block signals.

## Sessions

- Consider major session behavior when evaluating setups.
- Track volatility around New York and London trading windows.
- Avoid assuming all setups are equally valid across all sessions.

## Setup Validation

A setup should require alignment across:

- Market structure
- Liquidity context
- ICT concept confirmation
- Risk-reward profile
- Confidence score
- Prop firm risk limits

If these elements conflict, Sentinel should wait or avoid.
